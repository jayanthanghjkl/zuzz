Routines

A routine is a stored sequence of ordinary tool calls, not a script and not a privileged path around the permission gate. Each step is judged on its own, so a routine can be half permitted at a given trust level — the seeds show it: start_work is only fully automatic at trust level 5, because its third step navigates a browser and browse_internet asks below that.

Stored in — config on purpose, not in the memory store, so a routine can be read and edited by hand.

Save a new routine

New routines are stored disarmed, whatever this form says. Creating a routine and arming it are two acts: a POST that did both would mean you could not read what you had just built before it started opening applications. Arm it from the list above when you have looked at it.

Each tool name must be one ZUZZ actually has, and the parameters must be ones its schema accepts — the server checks both and refuses the save with the reason if not. Parameters are not optional in practice: most tools require one, so a step line without them could never be saved.

Habits ZUZZ has noticed

Repeated sequences in the activity log. Read-only: noticing a pattern is not deciding to act on it, and nothing here builds or arms a routine on its own.

Plan runs nothing

Press Plan on a routine and every step comes back with the verdict it would get at the current trust level. All of them are resolved before any of them would run, so you see the whole picture rather than discovering the refused step after the first three have already happened.

There is no endpoint that executes a whole routine, and that is the point rather than an omission: the permitted steps are issued one at a time, each through the same gate as any other action. Ticking a step here records that you approve it; it does not unlock anything by itself.
